# 多项目统一身份接入约定

项目默认使用可管理的本地账户。大平台尚未上线；本接口已实现并完成签名、角色、过期、跨项目和重放测试，尚未连接实际统一身份服务。

## 环境配置

- PROJECT_ID：项目稳定标识，默认dayun-g0104，须与大平台登记一致。
- AUTH_MODE：local保留本地登录，可同时显示已配置的统一登录；sso只接受统一登录，已有本地会话也失效。
- SSO_ISSUER：受信任签发方的完整标识。
- SSO_LOGIN_URL：大平台HTTPS登录/授权入口。
- SSO_JWKS：RSA公钥集合JSON，含keys数组和各公钥的kid/kty/n/e，不含私钥。

## 流程

1. 项目登录页调用POST /api/auth/sso/challenge。服务器设置5分钟HttpOnly nonce cookie，返回带nonce、audience及redirect_uri的统一入口。
2. 大平台验证自己的登录会话和用户的项目权限。已登录大平台的用户无需再次输入密码。
3. 大平台用私钥签发RS256 JWT，重定向到 `https://项目域名/sso/callback#ticket=JWT`。令牌放URL片段，回调读取后立即清除；不要放查询串、日志或浏览器存储。
4. 回调向POST /api/auth/sso/exchange提交JSON ticket。服务端验证签名和声明、消费一次性jti，建立HttpOnly/Secure项目会话。

签名头含alg=RS256、受信任kid。声明含：iss与SSO_ISSUER完全一致，aud与PROJECT_ID完全一致；sub为稳定用户ID；name为显示名称；jti每次唯一；iat/exp为Unix秒数，票据最大有效期5分钟；nonce匹配challenge；project_roles对象以项目ID为键、viewer或admin为值；session_seconds为可选会话时长（最长3600秒）。

浏览器传来的角色参数或未签名票据均不能授予权限。大平台须按用户真实项目授权签发，不能照抄客户端请求的角色。JWKS公钥轮换应先添加新key、切换签名，再移除旧key。

项目会话最长1小时。主平台退出/停用的即时联动、具体OIDC提供方适配和项目总导航，需在大平台落地时对接；当前接口不宣称已具备跨站实时单点退出。

## 数据隔离

当前每个部署拥有自己的数据库和文件存储。大平台可通过项目ID组织入口和成员权限。若未来把多个项目合并到同一数据库，需要为业务表和全部查询加入项目隔离条件，不能仅靠前端菜单隔离。
